# Блокировка автоматической проверки штатным RSS

## Причина

Известные стандартные пределы бота / программы 80 / 110 МиБ оставались прежними,
когда измеренное суммарное потребление уже достигло около 115–116 МиБ. Обновление
подписок и ночной полный пул откладывались до сетевой работы при достаточном
запасе свободной ОЗУ. У статуса существовал аналогичный предел 100 МиБ.
Небольшая разница последних трёх дней сама по себе не доказывает утечку.

Ручной полный прогон проверял worker, но не автоматический допуск при актуальном
потреблении памяти. Августовская приёмка расписания не заменяла повторную проверку
после последующих изменений программы.

## Исправление и защита

Три класса задач проверяют свежую доступную память с резервом на свою работу.
Только известные старые стандартные RSS-пределы заменяются этой политикой;
нестандартные ограничения сохраняются. Для строгой старой политики есть режим
`rss`. Настройки не переписываются, предыдущая версия при откате читает те же
значения. Сохранены CPU, load, занятость, обслуживание и текущие guards worker.

Пропущенные дни объединяются в текущую очередь с сохранением прогресса. Веб
отдельно показывает ручную и автоматическую историю и причину ожидания.
Логи имеют ограничение во время непрерывной работы; постоянный fd сохраняется,
архивы не создаются. Для внешних некооперативных writers сохранение одновременно
пишущейся диагностической строки при copy/truncate остаётся best effort.

## Проверки

Целевые тесты выполняют реальные функции планировщика, допуска и обновления
подписок вместе; только внешние измерения, сетевой ответ и запуск worker заменены
стендом. Покрыты старые/новые RSS, свободная ОЗУ, CPU/load, пользовательские пределы,
maintenance, несколько суток ожидания, перезапуск, прогресс и отсутствие дублей.
Проверки журналов включают потоки и POSIX-процессы, UTF-8, открытый append-fd и
отказ от перехода по symlink. UI проверяется в трёх режимах и на узких экранах.

Приёмка на роутере требует именно автоматического запуска после GitHub
update → rollback → update; ручной прогон не считается заменой. Чистая установка
рабочего роутера и суточное наблюдение в согласованный объём не входят.

В оба локальных review-prompt добавлено правило проверки автоматического допуска
при измеренном стабильном RSS. Итоговые результаты оборудования фиксируются
отдельно после выполнения, а не объявляются заранее успешными.
