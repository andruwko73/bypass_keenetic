# Горячая смена ключей: расширение допуска

Проверяемый официальный core: Xray 26.2.6, revision 12ee51e4. Один общий Xray сохраняется. Способы применения одинаковы для ручного выбора и автоматики.

| Пул | Допущенный вариант | Действие |
| --- | --- | --- |
| Vless 1/2 | TCP/raw, TLS/REALITY, проверенные Vision/mux сочетания | Замена выхода через фиксированный balancer |
| VMess | TCP/raw, без TLS или с TLS, mux | Замена выхода |
| Trojan | TCP/raw, без TLS или с TLS | Замена выхода и только S22trojan |
| Shadowsocks | Штатный TCP/raw | Замена выхода и только S22shadowsocks |
| Hysteria2 | TLS, обычные параметры и Salamander | Замена выхода при совместимом кеше назначения |

Старые TCP/UDP соединения Xray продолжают использовать прежний обработчик после удаления ссылки из manager. Потоки отдельной службы Trojan/Shadowsocks могут прерваться при её собственном перезапуске; обещание непрерывности относится к общему Xray и другим протоколам.

## Согласованность отдельных служб

Сначала проверяются кандидат и новый выход Xray. Общий журнал сохраняет старые/новые конфигурации, receipt и метаданные пула. После записи файлов перезапускается только фиксированная служба протокола; её процесс с ожидаемым файлом настроек должен владеть слушающим портом. Лишь затем журнал становится committed. При отказе возвращаются файлы, собственная служба и balancer. Неопределённый результат блокирует следующую смену, а не вызывает общий restart. При запуске незавершённый журнал восстанавливается до подтверждения состояния ядра.

## Ограничения Hysteria2

В upstream [XTLS/Xray-core#5911](https://github.com/XTLS/Xray-core/issues/5911) описан кеш по адресу без учёта auth. На официальном 26.2.6 это воспроизведено локально: запрос с намеренно неправильным новым паролем продолжает работать через ранее созданный клиент. Поэтому успешный HTTP-запрос недостаточен для подтверждения смены.

Программа хранит в RAM только отпечатки назначения и полной конфигурации каждого использованного Hysteria2-выхода. В историю попадают и неудачные попытки; возврат к тем же параметрам разрешён, изменение параметров ранее использованного адреса требует прежнего контролируемого применения с перезапуском. История привязана к процессу ядра и очищается только после подтверждённой новой загрузки. Потерянная/повреждённая история блокирует горячую операцию. Число назначений ограничено 32 за жизнь процесса — это ограничение удерживаемого кеша, не исправление ядра.

WS/gRPC/XHTTP и расширенные QUIC-параметры пока не допущены. В gRPC/XHTTP официальный core также содержит глобальные кеши, привязанные к stream config; включать их только после проверки освобождения ресурсов, а не по одному успешному запросу. Первое добавление протокола меняет inbounds/rules и остаётся структурной операцией. Ядро, firewall, порты и маршруты этим расширением не заменяются.

## Приёмка

Локальные тесты проверяют TCP/UDP до/после смены и отката, независимые потоки, отказ здоровья кандидата, ошибку диска, потерю ответа API, отказ собственной службы и её отката, восстановление после прерывания записи. Hysteria проверяется официальным локальным сервером, включая Salamander и отрицательное воспроизведение коллизии пароля. Аппаратная приёмка и ресурсы фиксируются отдельно после установки опубликованного коммита с успешным CI; локальный тест не заменяет проверку роутера.
